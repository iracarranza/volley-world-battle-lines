# Architectural Reconstruction Study — Repo Handoffs

This folder defines the **future six-run architecture discovery process** for Volley World: Battle Lines. It is not the completed architectural reconstruction and does not itself refactor gameplay code.

## Operational sequence

1. Read [EXECUTION_PROTOCOL.md](EXECUTION_PROTOCOL.md). Freeze a source commit, approved design-evidence manifest, and prompt digest.
2. Give [RECONSTRUCTION_HANDOFF.md](RECONSTRUCTION_HANDOFF.md) **unchanged** to each of six isolated agents. Give each the same read-only snapshot, equivalent tools and no ability to see another attempt's artifacts.
3. Quarantine and seal every candidate's full specification, semantic vocabulary, causal models, architectural ADRs, design–code atlas, development constitution, coverage and test report.
4. Verify the run manifests and isolation conditions. Do not silently synthesize contaminated or mixed-revision outputs.
5. Give accepted sealed packages simultaneously to a separate agent using [SYNTHESIS_HANDOFF.md](SYNTHESIS_HANDOFF.md). Normalize by actual game responsibilities and premises **before** comparing subsystem architecture.
6. Review the unified architecture, remaining designer decisions, adversarial tests and migration plan **before authorizing implementation**.

## Design philosophy

- **Methodological consistency without predetermined conceptual conclusions.** The same evidence and quality requirements apply to all runs. Each agent can discover its own ontology, state model, system boundaries and abstractions.
- **Justification-first synthesis.** Competing ADR premises, evidence, alternatives, and counterexamples are the primary material. Agreement is not proof; minority proposals may be superior.
- **Semantic reproducibility.** An eventual coder should understand how player intent becomes game outcome using stable names, variable meanings, ownership, causal direction and extension procedures.
- **Evidence over false completeness.** Keep intended design, implemented behavior, actually verified results, and proposed changes distinct.
- **Architectural longevity without rigidity.** Foreseeable mechanics should have predictable conceptual addresses; genuinely new concepts follow explicit change governance.

## What was committed

The protocol and two handoffs are development *instructions*. The six independent codebase runs and their ADR-led synthesis have **not yet been performed**. No claims of discovered architecture, six-way statistical independence, actual runtime correctness, or test success are implied.
